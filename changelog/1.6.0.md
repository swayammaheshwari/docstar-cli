# 1.6.0

## Breaking

- `init` takes the collection's **slug** and nothing else: `docstar-cli init msg91`. A domain
  (`docs.msg91.com`), `--collectionId` and sub-path hosting are no longer accepted; passing anything that
  is not a slug says so. The docs are read from `https://api.docstar.io` (`GET /p/generate-module-json?slug=`),
  or from another DocStar API with the new `--api <url>` flag (a local or dev one). Collections installed
  by earlier versions keep working: re-run `init <slug>` to store the API they come from.

## New features

- `key request` and `key save --payload <encrypted> [--env .env]`: get an API key that a DocStar MCP
  tool created for the signed-in user into the project's env file, without the AI assistant reading it
  and without anything storing it. `key request` makes an X25519 keypair, keeps the private key in
  `~/.docstar/pending-keys/` (owner-only, 10 minutes) and prints the public key. The MCP tool encrypts the
  key with it (X25519 + HKDF + AES-256-GCM) and returns a payload. `key save` decrypts it, sets the variable
  the tool chose, keeps other lines, makes the file readable by its owner only, adds it to `.gitignore`,
  deletes the private key (a payload works once) and prints only the key's last 4 characters. The format
  for tool authors is in `docs/key-handoff.md`.
