# 1.1.0

## New features

- **Multi-collection support**: `docstar-cli init <domain>` can now be run against multiple docs
  sites/collections without wiping previously-installed ones. Everything is namespaced by a
  collection's **CLI name** (`docProperties.cliName`, lowercase letters/numbers/`-`/`_`,
  auto-derived from the collection name if not set): `docstar-cli <collection> <module> <endpoint>`.
- **`docstar-cli list`**: list every installed collection, the modules within one
  (`list <collection>`), or every endpoint of one module (`list <collection> <module>`) — reads
  entirely from local state, no network call.
- **`docstar-cli mcp`**: starts an MCP (Model Context Protocol) server exposing every installed
  endpoint, across all installed collections, as a callable tool for AI clients (Claude Desktop,
  Claude Code, etc.). Tool names follow the same `<collection>__<module>__<endpoint>` hierarchy.
- **Interactive parameter prompts**: any required parameter not passed as a `--flag` is now
  collected via an interactive prompt instead of failing, so `docstar-cli <collection> <module>
  <endpoint>` works with zero flags.
- **`init` module picker overhaul**: modules now start unchecked by default (previously all
  pre-checked), and a `➤ Select all modules` entry was added so installing everything is still one
  keystroke away. The checklist also shows each module's endpoint count.
- **Shell tab-completion**: a purpose-built completion (`docstar-cli completion-script`) that
  completes only module names (once a collection is typed) and endpoint names (once a collection
  and module are typed) — it deliberately never completes the collection name itself or top-level
  commands like `list`/`init`/`mcp`. Works in both bash and zsh.
- **`AGENTS.md`** added, documenting the project for AI agents: the collection → module → endpoint
  hierarchy, where key logic lives, known gotchas, and a standing instruction to bump this
  `version` field on every AI-driven code change.

## Bug fixes

- **JSON body type coercion**: CLI flag values (always strings) are now coerced back to the
  request body template's real type before sending — a boolean field becomes a real
  `true`/`false`, an array field becomes a real array, instead of the literal string `"true"` or a
  stringified array.
- **Duplicate case-variant headers**: an endpoint whose stored headers include both e.g.
  `Content-Type` and `content-type` no longer sends both as separate header lines (which was
  silently breaking body parsing on some receiving servers) — headers are now deduped
  case-insensitively.
- **Invalid generated command syntax**: a parameter name containing a quote or stray HTML markup
  (from a rich-text-authored endpoint field) could produce a generated command file with broken
  JS syntax. All dynamic values embedded into generated command source are now escaped via
  `JSON.stringify` instead of raw string interpolation.
