# 1.8.0

## New features

- `login <collection>`: signs you in to a collection's platform in your browser (OAuth 2.0), with the
  same OAuth app the docs owner set up for their DocStar MCP server. DocStar's API holds the client
  secret and does the code exchange (`POST /p/cli-auth/start`, `/poll`, `/refresh`); the CLI only gets
  your tokens, saved in `~/.docstar/credentials.json` (readable by you only) and never printed.
  - `--no-browser` only prints the link; `--no-wait` prints it and exits, `--continue` finishes the
    sign-in (for AI assistants that run one command at a time). `--api <url>` (or `DOCSTAR_API_URL`)
    picks the DocStar API; by default the one the collection was installed from.
  - Tokens are refreshed through DocStar before they expire; a token the API refuses (401) is
    refreshed once and the call retried. A refused refresh ends the sign-in.
- `logout <collection>`, and `auth status [collection]`: what each installed collection needs (its
  API keys, sign-in) and whether it's set up. Saved keys show only their last 4 characters.
- **Sign-in is the default.** An endpoint that sends the sign-in header (the one the docs owner chose
  for sign-in, default `Authorization`) gets your token there, unless:
  - the docs owner marked that header as an API key (`credential: "apiKey"` on the row in module.json), or
  - you gave its value yourself (a flag, `config set`, or a key stored by `key save`).
- **API keys only where marked.** For a header or query param the docs owner marked as an API key, the
  CLI sends your key: a flag on the call, else the one saved with `config set` / `key save`.
- Both are checked **before** calling. In a terminal a missing key is asked for (hidden) and can be
  saved, and a missing sign-in offers to run `login`; when an AI assistant or CI runs the command it
  stops with what to do and exits with code 4. The CLI never reads your environment or `.env` for keys.
- When the API refuses a key or sign-in, `hint` says which one and where it came from, never its value.
- `--help`, `list` and the `mcp` tool descriptions say which API key or sign-in each endpoint needs.
- Endpoint commands exit with code 1 when the API answers 4xx/5xx (the response is still printed).

## Changed

- `init` also refuses the slugs `auth`, `login` and `logout` (now CLI commands).

Run `init` again for each installed collection to get the new behaviour in its commands.
