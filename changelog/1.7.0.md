# 1.7.0

## New features

- `login <collection>`: signs you in to a collection's platform in your browser (OAuth 2.0), with the
  same OAuth app the docs owner set up for their DocStar MCP server. After that, the collection's
  commands and `mcp` tools send your access token (in the endpoint's token header from module.json's
  `auth`, else `Authorization: Bearer`). DocStar's API holds the OAuth client secret and does the
  code exchange (`POST /p/cli-auth/start`, `/poll`, `/refresh`); the CLI only gets your tokens.
  - Tokens are saved in `~/.docstar/credentials.json` (readable by you only) and never printed.
  - An expiring token is refreshed before the call; a token the API refuses (401) is refreshed once
    and the call retried. A refused refresh ends the sign-in and says to run `login` again.
  - `--no-browser` only prints the link. `--no-wait` prints the link and exits, and `--continue`
    finishes the sign-in, for AI assistants that run one command at a time.
  - `--api <url>` (or `DOCSTAR_API_URL`) picks the DocStar API, default `https://api.docstar.io`.
- `logout <collection>`: deletes the saved sign-in on this computer.
- `auth status`: lists the collections you're signed in to and when their tokens expire.
- A call the API refuses with 401 while you're not signed in now says how to sign in or save an
  API key (`hint` in the output).
