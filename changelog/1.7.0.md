# 1.7.0

## New features

- `key emit <slug> <name> [--env .env] [--var NAME]`: writes a key stored by `key save` to a project's env
  file, as the variable the MCP tool chose (or `--var`). Other lines are kept, the file is made readable by
  its owner only and added to `.gitignore`, and only the key's last 4 characters are printed.
- Commands of a collection send a stored key themselves, with the scheme the tool chose in front of it
  (`Authorization: Bearer <key>`), so no flag is needed.

## Changed

- `key save --payload <encrypted>` no longer writes `.env` (its `--env` flag is gone). It stores the key in
  docstar-cli, under the collection named in the payload (which must be installed with `init <slug>`), in
  `~/.docstar/config.json`, together with the variable name and header scheme the tool chose. Use `key emit`
  to write a project's `.env`. The payload now carries `slug`, `name`, `envVar` and an optional `prefix`;
  tools that built payloads for 1.6.0 must add them (see `docs/key-handoff.md`).
- `config get` shows credentials as their last 4 characters; pass `--reveal` for the whole value.
- `config set` makes `~/.docstar/config.json` readable by its owner only.
- `init` refuses slugs that are the names of CLI commands (`init`, `key`, `config`, `list`, `mcp`, `clean`,
  `complete`, `completion`, `completion-script`, `help`); hitman-api no longer creates collections with them.
